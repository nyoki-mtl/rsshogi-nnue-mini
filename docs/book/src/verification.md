# 開発時の測定結果と検証範囲

エンジンの動作確認、探索速度、対局での成績は別々に確かめる。
以下は開発時に得た結果であり、現在の実行ファイルの棋力や、別の持ち時間での成績を保証するものではない。
比較ごとに基準版、評価関数、開始局面、時間条件が異なるため、行ごとの数値を足し合わせることもできない。
数値は開発時の対局記録と測定記録に基づくが、それらの実行成果物は公開snapshotに含めていない。

## `.rsnn`評価関数で確認したこと

512幅・Threatなし・PSQTありのSFNNv15 packageを84エポック学習し、所定のvalidationとexportまで完了した。
そのpackageはローカルのconsumerで形式を検査し、miniの通常版で`isready`と短い探索を確認した。
内蔵AVX2版でも外部評価ファイルなしで`isready`、短い探索、`stop`、`quit`を確認した。
試験学習した別のpackageでは、参照consumerとminiの評価値が3局面で一致した。

学習時の厳格なconsumer適格性検査は、固定した実装のrevisionが一致せず失敗した。
その後、固定版を揃えて同じ本学習packageを再検査し、package digest、評価仕様、実装revisionの一致を確認した。
digest、評価仕様、revisionをそれぞれ誤らせた負例も拒否した。
miniのscalar全再計算は参照実装と5局面で同じ評価値を返し、実モデルを使った6,000回のランダム操作（着手・取り消し・null手）では差分更新と全再計算が一致した。
この後日の適格性確認は、学習実行時に記録された検査失敗を遡って消すものではない。
読み込みの成功と短いUSI探索は、棋力やモバイル実機上の性能の証明でもない。
packageの検証内容と再現手順は[評価関数](nnue.md)を参照。

## 速度の測り方

高速化の検討では、64局面をそれぞれ30万ノード読む固定ノードbenchで、処理速度と探索結果の署名を比べた。
専用CPU上で旧版と候補版を交互に実行し、組ごとのNPS比の中央値を取った。
不成の省略前の採用版は、開始時の版に対して7950X3Dの測定coreで1.212倍（12組、1.201〜1.222倍）だった。
不成の省略は、別の5900Xで直前の版に対して1.018倍（12組、1.012〜1.030倍）だった。
測定CPUと比較基準が違うので、この二つの倍率を掛けて現在版のNPSとはしない。

固定ノードの署名が一致した変更は、その64局面で手、深さ、評価値、ノード数、読み筋が一致したという意味である。
すべての局面で探索木が同じことの証明ではない。
段階的な手の生成や不成の省略は探索木も変えるため、実時間の対局で別に判定した。

## Floodgateでの運用とレート

USIの`stop`や`quit`までのローカル確認と、外部CSAサーバでの運用確認は異なる。
2026年9月30日00:00 JST、上記84エポック評価packageを内蔵した版をFloodgateへ接続し、最初の1局を54手で完走した。
ソースは`04c6cb0`、CPUはRyzen 7 9700X、設定は`Threads=4`、`USI_Hash=128`、`USI_Ponder=true`、中継は`rsshogi-csa` 0.1.3である。
`komadokun_depth9`を相手に後手で勝ち、イベントログに警告はなかった。
エンジン通信では`go`40回に対して`bestmove`40回、対局前の`usinewgame`と終了時の`quit`、中継の`bridge_stop`を確認した。
この1局は接続と終局処理の確認であり、レーティングや長時間運用の結果ではない。

同じ実行ファイルと設定で、その後も新しい対局名`rss-mini-84e-20260929`で測定した。
2026年9月30日16:30 JST開始の対局までに計24局を終え、17勝7敗だった。
[Floodgateの対局者ページ](https://wdoor.c.u-tokyo.ac.jp/shogi/x/2026/player/rss-mini-84e-20260929+72a7fa5.html)のレート欄は、同日17:24 JSTの確認時点で3444（**R3444**）だった。
初回の1局を除く23局のイベントログには警告やエラーがなく、エンジン通信では`go`2332回に対して`bestmove`2332回を確認した。
レートはこの対局名、相手、持ち時間、CPU、評価packageで得た観測値であり、別の構成の棋力を保証しない。

公開ビルドを特定のCPU、評価package、GUIや中継、時間設定で使う場合は、実際の環境で1局の完了、反則と時間切れの有無、各`go`への`bestmove`、次局の初期化、正常終了を記録する。
[CSA接続の手順](operations/csa.md)と[ShogiArenaでの比較](operations/shogiarena.md)を参照。
