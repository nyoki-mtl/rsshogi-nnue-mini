# 手の並べ替えとSEE

alpha-betaの削減は最善手を早く読むほど大きくなる。
しかし、どれが最善手かは読む前にはわからない。
**手の並べ替え**（move ordering）は、探索前に得られる情報だけで「最善手である見込みの高い順」を作る。

## 並べ替えの点数

手には計算の軽い点数を付け、降順に並べる。
点数には、置換表の最善手、捕獲する駒の価値、成り、killer、historyを使い、捕獲と成りには王手の加点も行う。
静かな手の王手判定は、並べ替えのためには行わない。

置換表の手が別格なのは、それが「実際に読んだ結果の最善手」だからである。
ほかの加点をすべて足しても追い越せない点数を与え、必ず先頭に置く。

## 段階ごとの生成

王手されていない主探索のノードでは、全合法手を先に生成しない。
次の順に、前の段階の手を読み終えて次の手が必要になった時点で生成する。

1. 置換表の最善手（この局面で合法なときだけ）
2. killer（合法で、この局面でも静かな手であるときだけ）
3. 捕獲（点数順）
4. 静かな手と、捕獲でない成り（点数順）
5. SEEが負の捕獲

beta cutoffの多くは置換表の手、killer、捕獲で起きる。
その場合、静かな手の生成も点数付けも行わない。
静かな手の点数は、前の段階の手を読んだ後で付けるため、それらの探索で更新されたhistoryを反映する。

王手されているノードと、singular extensionの判定で置換表の手を除いて読むノードは、読む対象の手をすべて先に生成して一度に並べる。
[静止探索](qsearch.md)も、生成した候補を一度に並べる。
一度に並べる場合も、置換表の手、killer、捕獲の層だけを先に並べ、静かな手の層はそれらを使い切ってから並べる。
上の層の点数は下の層より必ず大きいため、順序は全体を一度に並べた場合と変わらない。

rootを除き、歩・角・飛が成れる手は成りだけを生成し、不成は生成しない。
これは読む手を減らす探索上の選択であり、不成が有利になる局面がないという意味ではない。
直前の版との実時間SPRTで採用を判断した（[測定結果](../verification.md)を参照）。
rootでは不成も含めた全合法手を読む。
合法手があるかどうかは、成りと不成が同じ移動なので変わらない。

生成器が出す手は、自玉を取らせないかどうかだけを確かめて合法手とする。
打ち歩詰めは生成器が検査しないため、歩の駒打ちだけは打ち歩詰めを含む判定を通す。

捕獲のSEEは、その手を取り出す時点で計算する。
SEEが負の捕獲は後回しにし、ほかの候補を返した後で、駒価値とSEEを反映した点数順に返す。
ただし、置換表の手はSEEが負でも先頭に残す。
この遅延計算により、beta cutoffで読む必要がなくなった捕獲のSEEを省ける。

**killer**は、ルートから同じ手数の別局面でbeta cutoffを起こした静かな手を2個まで覚えたものである。
兄弟局面は似ているので、隣で刈れた手はここでも刈れる見込みが高い。
**main history**は、手番と移動元、移動先ごとに、静かな手の成功と失敗を記録する。
beta cutoffを起こした手に報酬を与え、それより前に試してalphaを上げられなかった静かな手には罰点を与える。
更新量は深さに応じて決め、値が飽和範囲に収まるように更新する。
**continuation history**は、1手前と2手前の「移動後の駒種と到達マス」に対する手の続き方を記録する。
静かな手の履歴スコアには、main historyと重み付きcontinuation historyの和を使う。
このスコアはLMRとhistory pruningにも使う。

killerは探索ごとに作り直すが、履歴の表は同じ対局の`go`をまたいで保持し、`usinewgame`で破棄する。
main historyは探索開始時に半減させる。
continuation historyは探索開始時には半減させず、個々の更新で値の大きさを制限する。

捕獲の分類と計算済みのSEEは、その後の探索と枝刈りへ渡す。
枝刈りに使う王手判定は、必要になった手について探索側で行う。

## SEEによる取り合いの見積もり

捕獲の良し悪しは、取った駒の価値だけでは決まらない。
歩で守られた銀を飛車で取れば、銀は得るが飛車を失う。
これを判定するには取り合いの応酬を最後まで考える必要があるが、そのために探索を呼んでいては本末転倒である。

**static exchange evaluation（SEE）**は、対象のマスへの取り合いだけを、局面を進めずに評価する。
手順は次のとおりである。

1. 最初の捕獲の駒得を記録する
2. 相手の攻撃駒のうち最も安いものが取り返すとして、その時点の駒得を記録する
3. 取り返した駒をoccupancyから外し、攻撃駒を求め直して2へ戻る（外した駒の陰にいた飛び駒の利きがここで現れる）
4. どちらかに攻撃駒がなくなったら、記録した列を後ろから畳み込む

畳み込みは`max`を取りながら戻るので、どちらの側も「これ以上取り返すと損」という時点で応酬を降りられる。
▲5五飛が、歩で守られた5四の銀を取る例で追う。
駒得は盤上の駒の消失と持ち駒の増加の両方を数えるため、駒価値の2倍で動く。

| 段階 | 記録される駒得（先手視点） |
| --- | ---: |
| 飛が銀を取る | +900 |
| 歩が飛を取り返すなら | +900 − 2,000 = −1,100 |
| 後ろから畳み込み | 後手は取り返しを選べるので min(+900, −1,100) = **−1,100** |

先手は銀得のつもりでも、SEEはこの捕獲を1,100点の損と判定する。
この値が並べ替えのクラスと値の両方に使われ、[静止探索](qsearch.md)では負のSEEの捕獲を読まない根拠になる。

## 近似の範囲と玉の安全性

このSEEはswap列の畳み込みであって、合法手の全探索ではない。
合法な取り返しの全探索と比べて、主に次の近似がある。

- pinは開始局面の状態でだけ判定する。取り合いが進んで駒が減った結果として生じたり解けたりするpinは追わない
- 合法手生成を使わないため、王手がかかっている局面でも取り合いだけを見る
- 各手番で最も安い攻撃駒を選び、ほかの駒で取り返す分岐は読まない

一方、玉の扱いは近似で済ませない。
玉での取り返しは、相手に攻撃駒が残っている間は行わず、玉の着地点はpinされた駒も含めた相手の利きで検査する。
ここを緩めると、SEEが「玉で取り返せるから得」と判定した読み筋の先で玉が取られる。
枝刈りの根拠に使う値なので、損得の精度より自殺手の排除を優先している。

## oracleとの一致

各plyで局面を複製し、合法な取り返しを全探索する正確なSEEもtest用に残している。
探索から呼ぶには重いため、swap版の結果を比較する**oracle**としてだけ使う。
通常の取り合いでは一致し、途中でpinが生じる局面では意図した近似差だけが現れることを回帰testで確認している。
