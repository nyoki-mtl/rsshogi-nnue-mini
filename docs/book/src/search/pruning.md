# 枝刈りと探索深さの調整

alpha-beta法は、同じ探索木に対するminimax値を保ちながら不要な枝を省く。
一方、この章の技法は、静的評価や手の順序を手掛かりに探索木そのものを小さくする。
最善手を読み落とす可能性があるため、適用条件と再探索の条件を決め、棋力への影響は対局で確かめる。

以下の深さは、特記しない限り主探索の各ノードで使う残り深さである。
**PVノード**は探索窓の幅が1より大きいノード、**非PVノード**は幅1の探索窓で読むノードを指す。
**静かな手**は、捕獲でも成りでもない手を指し、駒打ちも含む。

## 実装している技法

| 技法 | 適用場所と主な条件 | 動作 |
| --- | --- | --- |
| internal iterative reduction（IIR） | TTの手がない、深さ2以上 | 残り深さを1減らす |
| reverse futility pruning | 非PV、王手なし、深さ9以下 | 静的評価から余裕幅を引いてもbeta以上なら打ち切る |
| null move pruning | 非PV、王手なし、静的評価がbeta以上、直前がnull moveでない | 手番を渡して浅く探索し、条件を満たせば打ち切る |
| ProbCut | 非PV、王手なし、深さ4以上 | betaに余裕幅を足した値をSEEで賄える捕獲を、静止探索と深さ-3の探索で確かめ、超えれば打ち切る |
| futility pruning | 王手なし、深さ6以下 | 静的評価に余裕幅を足してもalpha以下なら、先頭以外の静かな非王手を省く |
| 捕獲のSEE枝刈り | 非PV、王手なし、深さ7以下 | 先頭以外で、交換損が深さに応じた閾値を下回る捕獲を省く |
| history pruning | 非PV、王手なし、深さ5以下 | 先頭以外で、履歴スコアが低い静かな非王手を省く |
| late move pruning（LMP） | 非PV、王手なし | 静かな非王手を、盤上の手と駒打ちに分けて個数で制限する |
| late move reductions（LMR） | 王手なし、順序の遅い静かな手と、SEEで損な捕獲 | 対数式で浅く読み、alphaを超えたら通常の深さで読み直す。損な捕獲は静かな手より1段浅く縮める |

静止探索に使うdelta pruningとSEE枝刈りは、[静止探索](qsearch.md)で説明する。
数値は現在の通常ビルドの既定値であり、調整用ビルドでは変更できる。

## 静的評価の補正と改善判定

主探索は、NNUEの生の評価値に**correction history**の補正を足して枝刈りを判断する。
この履歴は、静かな手が最善になったノードなど、所定の条件を満たす探索結果と生の評価値との差を記録する。
持ち駒、歩の配置、両玉の位置を手掛かりに補正を求め、既定では±67点に制限する。
補正後の評価も通常評価の範囲へ収める。
TTへ保存する静的評価は補正前の値であり、利用するワーカーの履歴に応じて補正し直す。

**改善あり（improving）**とは、現在の静的評価が同じ手番の2手前より高いことを指す。
比較する評価値が片方でも欠けていれば、改善なしとして扱う。
null moveの子には空の静的評価履歴を渡し、パスをまたぐ値を比較しない。

## IIR

TTに最善手が残っていない深いノードでは、有望な手を先頭へ置く情報が足りない。
IIRは深さ2以上で残り深さを1減らし、その訪問にかかる探索量を抑える。
以後の枝刈りやLMRは、この調整後の深さを使う。
IIR自体は、元の深さでの再探索を必ず行う仕組みではない。

## reverse futilityとfutility

**reverse futility pruning**は、静的評価が十分高い浅い非PVノードを打ち切る。
深さ9以下で、`静的評価 − 128 × (深さ − improving) ≥ beta`なら静的評価を返す。
式中の`improving`は、改善ありなら1、それ以外なら0である。
改善ありのときは差し引く余裕幅が小さくなり、打ち切りやすくなる。

**futility pruning**は、静的評価が低いノードで一部の手を省く。
深さ6以下で`静的評価 + 173 × 深さ ≤ alpha`なら、先頭以外の静かな非王手を読まない。
捕獲と成りは対象外だが、静かな駒打ちは対象に含む。
どちらの技法も、王手されているノードには適用しない。
余裕幅は形勢の変化を見積もるための値であり、実際の評価変動の上限ではない。

## null move pruning

**null move**は、盤面と持ち駒を変えずに手番だけを相手へ渡す探索用の操作である。
手番を渡して浅く読んでもbeta以上なら、通常の着手でもbeta以上を得られると見込んで打ち切る。
ただし、どの手を指しても不利になる局面では、この見込みが外れる。

適用するのは、王手されていない幅1の探索窓で、静的評価がbeta以上、betaが被詰み側の帯より大きく、直前の手がnull moveではない場合である。
深さの下限は設けず、縮小後の深さが0なら静止探索へ進む。
縮小量は次の式で決める（除算は整数除算）。

```text
R = 3 + 深さ / 2 + min((静的評価 − beta) / 199, 3)
子の深さ = max(深さ − 1 − R, 0)
```

null moveの探索がbeta以上を返し、元のノードの深さが12以上なら、手番を戻した同じ局面を`深さ − R`でもう一度探索する。
この検証でもbeta以上なら打ち切る。
検証探索の配下でnull moveを全面的に禁止する実装ではない。
打ち切る際はbetaを返し、TTへ最善手なしの`Lower`エントリを保存する。
null moveは駒の特徴量を変えないため、NNUE accumulatorは更新しない。

## SEEと履歴による枝刈り

主探索の**SEE枝刈り**は、深さ7以下の非PVノードで、`SEE < −90 × 深さ²`となる捕獲を省く。
先頭の手と王手回避は残すが、王手を掛ける捕獲を一律に残す条件はない。
静止探索のSEE枝刈りとは適用条件が異なる。

**history pruning**は、深さ5以下の非PVノードで、`履歴スコア < −2080 × 深さ`となる静かな手を省く。
履歴スコアはmain historyと重み付きcontinuation historyの和である。
先頭の手、王手を掛ける手、王手回避は残す。

## LMP

LMPは、並べ替えの後ろにある静かな非王手を、対象手の個数で制限する。
深さによる適用上限はなく、非PVかつ王手されていないノードに適用する。
盤上の手の上限は次の式で決まる。

```text
上限 = (1 + 深さ²) / (2 − improving)
```

整数除算なので、改善なしの深さ1、2、3では、それぞれ2、3、6手までとなる。
改善ありなら4、7、12手まで許す。
比較用の評価値が欠けた場合も、改善なしの上限を使う。

駒打ちは盤上の手とは別に数える。
駒打ちの上限は、盤上の上限を`SearchDropLmpDivisor`（既定2）で割り、最低1手を残した値である。
このパラメータが0なら、駒打ちのLMPは無効になる。
個数は、先行するfutilityやhistory pruningで省かれず、LMPの判定まで到達した対象手を数える。

## LMR

LMRは、順序の遅い静かな手を通常より浅い幅1の探索窓で読む。
非PVノードでは3手目以降、PVノードでは4手目以降を候補とし、王手回避には適用しない。
王手を掛ける静かな手も、静かな非王手と同じ縮小量で読む（調整用の`SearchCheckLmrOffset`で縮小を控える段数を変えられる。既定は0）。

縮小量の基礎値は、`floor(ln(深さ) × ln(手の添字) × 100 / 221)`である。
添字は0始まりで、事前計算する表では深さと添字をそれぞれ63以下に収める。
基礎値に対し、PVなら1減らし、改善なしなら1増やし、履歴スコアに応じてさらに±1以内で調整する。
最終的には`0..=深さ−2`に収めるため、実際に浅くなるのは深さ3以上で、子の深さは1以上に保つ。

浅い探索がalphaを超えたら、通常の深さで幅1の探索をやり直す。
その結果がalphaとbetaの間なら、PVSの通常の窓でも読み直す。
浅い探索がalphaを超えなかった手は、そのまま確定するため、読み落としの可能性が残る。

## singular extension

枝刈りと逆向きに、特定の手だけを深く読む仕組みもある。
置換表に最善手と下限値（`Lower`か`Exact`）があり、そのdepthが現在より3浅い以内なら、その手を除いた残りの手を半分のdepthで読む。
窓は置換表の値から`2 × depth`を引いた値`singular_beta`の直下に置く。
除いた手がどれも`singular_beta`に届かなければ、置換表の最善手だけが局面を支えていると見て、その手を1手深く読む。
逆に除いた手でも`singular_beta`に届き、しかも`singular_beta`がbeta以上なら、betaを超える手が複数あるので、このノードを`singular_beta`で打ち切る（multi-cut）。

判定の探索は通常のノード探索と同じ並べ替えと枝刈りを使い、除いた手だけを読まない。
その結果は最善手を含む本来の値ではないので、置換表では打ち切らず、保存もしない。
深さ6未満のノード、root、詰みの値、iterationのdepthの2倍以上のplyでは試さない。

## 枝刈り後の置換表

主探索は、beta cutoffを起こした結果を`Lower`として保存する。
cutoffせずに終わり、省いた手や再探索しなかったLMRの手がある場合は、`Exact`を使わず`Upper`として保存する。
これは選択的な探索で得た値を再利用する実装上の方針であり、省いた手まで含めたminimax値の厳密な上界を証明するものではない。

静止探索は別の保存条件を使う。
枝刈りしたノードでは、beta cutoffで得た`Lower`だけを保存する。
詳細は[置換表](tt.md)と[静止探索](qsearch.md)を参照。

調整用ビルドは35個の探索パラメータ、時間管理の定数5個と`FV_SCALE`を公開する。
SPSAの設定例は、そのうち探索パラメータ7個と`FV_SCALE`を選ぶ（[運用](../operations/shogiarena.md)を参照）。
