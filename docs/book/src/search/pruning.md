# 枝刈りと探索深さの調整

alpha-beta法は、同じ探索木に対するminimax値を保ちながら不要な枝を省く。
一方、この章の技法は、静的評価や手の順序を手掛かりに探索木そのものを小さくする。
最善手を読み落とす可能性があるため、適用条件と再探索の条件を決め、棋力への影響は対局で確かめる。

以下の深さは、特記しない限り主探索の各ノードで使う残り深さである。
**PVノード**は探索窓の幅が1より大きいノード、**非PVノード**は幅1の探索窓で読むノードを指す。
**静かな手**は、捕獲せず、歩、香、飛の成りでもない手を指す。
駒打ちと、駒を取らない銀、桂、角の成りも含む。

## 実装している技法

| 技法 | 適用場所と主な条件 | 動作 |
| --- | --- | --- |
| internal iterative reduction（IIR） | TTの手がない、深さ2以上 | 残り深さを1減らす |
| reverse futility pruning | 非PV、王手なし、深さ12以下 | 静的評価から余裕幅を引いてもbeta以上なら打ち切る |
| null move pruning | 非PV、王手なし、静的評価がbetaより5点以上高く、直前がnull moveでない | 手番を渡して浅く探索し、条件を満たせば打ち切る |
| ProbCut | 非PV、王手なし、深さ4以上 | betaに194を足した値をSEEで賄える捕獲を、静止探索と深さ-3の探索で確かめ、超えれば打ち切る |
| futility pruning | 王手なし、深さ7以下 | 静的評価に余裕幅を足してもalpha以下なら、先頭以外の静かな非王手を省く |
| 捕獲のSEE枝刈り | 非PV、王手なし、深さ5以下 | 先頭以外で、交換損が深さに応じた閾値を下回る捕獲を省く |
| 静かな手のSEE枝刈り | 非PV、王手なし、深さ3以下 | 先頭とTTの手を除き、王手にならず交換損が大きい移動と打ち手を省く |
| history pruning | 非PV、王手なし、深さ3以下 | 先頭以外で、履歴スコアが低い静かな非王手を省く |
| late move pruning（LMP） | 非PV、王手なし | 静かな非王手を、盤上の手と駒打ちに分けて個数で制限する |
| late move reductions（LMR） | 王手なし、順序の遅い静かな手と、SEEで損な捕獲 | 対数式と局面の性質で浅く読み、alphaを超えたら読み直す。損な捕獲は基礎値より3段浅く縮める |

静止探索に使うdelta pruningとSEE枝刈りは、[静止探索](qsearch.md)で説明する。
表は現行実装で使う条件を示す。

## 静的評価の補正と改善判定

主探索は、NNUEの生の評価値に**correction history**の補正を足して枝刈りを判断する。
この履歴は、静かな手が最善になったノードなど、所定の条件を満たす探索結果と生の評価値との差を記録する。
持ち駒、歩の配置、両玉の位置を手掛かりに補正を求め、既定では±45点に制限する。
補正後の評価も通常評価の範囲へ収める。
TTへ保存する静的評価は補正前の値であり、利用するワーカーの履歴に応じて補正し直す。

**改善あり（improving）**とは、現在の静的評価が同じ手番の2手前より高いことを指す。
比較する評価値が片方でも欠けていれば、改善なしとして扱う。
null moveの子には空の静的評価履歴を渡し、パスをまたぐ値を比較しない。

## IIR

TTに最善手が残っていない深いノードでは、有望な手を先頭へ置く情報が足りない。
IIRは深さ2以上で残り深さを1減らし、その訪問にかかる探索量を抑える。
以後の枝刈りやLMRは、この調整後の深さを使う。
IIR自体は、元の深さでの再探索を必ず行う仕組みではない。

## reverse futilityとfutility

**reverse futility pruning**は、静的評価が十分高い浅い非PVノードを打ち切る。
深さ12以下で、`静的評価 − 132 × 深さ ≥ beta`なら静的評価を返す。
置換表に無い局面でこの打ち切りが起きたときは、返した値（補正後の静的評価）をその深さの下界（`Lower`）として、補正前の静的評価とともに置換表へ保存する。
次にこの局面へ来たときは静的評価を計算し直さずに済み、同じ深さ以下でbetaがこの値以下なら、静的評価とbetaの差が余裕幅に足りなくても置換表で打ち切る。
改善ありのときに余裕幅を緩める調整（`rfp_improving_depth`）も実装にはあるが、既定値の0では使わない。

**futility pruning**は、静的評価が低いノードで一部の手を省く。
深さ7以下で`静的評価 + 299 × 深さ ≤ alpha`なら、先頭以外の静かな非王手を読まない。
捕獲と歩・香・飛の成りは対象外だが、静かな駒打ちと、駒を取らない銀・桂・角の成りは対象に含む。
どちらの技法も、王手されているノードには適用しない。
余裕幅は形勢の変化を見積もるための値であり、実際の評価変動の上限ではない。

## null move pruning

**null move**は、盤面と持ち駒を変えずに手番だけを相手へ渡す探索用の操作である。
手番を渡して浅く読んでもbeta以上なら、通常の着手でもbeta以上を得られると見込んで打ち切る。
ただし、どの手を指しても不利になる局面では、この見込みが外れる。

適用するのは、王手されていない幅1の探索窓で、静的評価がbetaより5点以上高く、betaが被詰み側の帯より大きく、直前の手がnull moveではない場合である。
深さの下限は設けず、縮小後の深さが0なら静止探索へ進む。
縮小量は次の式で決める（除算は整数除算）。

```text
R = 4 + 深さ / 3 + min((静的評価 − beta) / 296, 3)
子の深さ = max(深さ − 1 − R, 0)
```

null moveの探索がbeta以上を返し、元のノードの深さが16以上なら、手番を戻した同じ局面を`深さ − R`でもう一度探索する。
この検証でもbeta以上なら打ち切る。
検証中の同じnodeではnull moveを再び試さず、子nodeでは通常どおり使う。
検証探索の配下でnull moveを全面的に禁止する実装ではない。
打ち切る際はbetaを返し、TTへ最善手なしの`Lower`エントリを保存する。
null moveは駒の特徴量を変えないため、NNUE accumulatorは更新しない。

## SEEと履歴による枝刈り

主探索の**SEE枝刈り**は、深さ5以下の非PVノードで、`SEE < −177 × 深さ²`となる捕獲を省く。
先頭の手と王手回避は残すが、王手を掛ける捕獲を一律に残す条件はない。
静止探索のSEE枝刈りとは適用条件が異なる。

深さ3以下では、静かな移動と駒打ちにも同じ交換損の閾値を使う。
移動先で相手が駒を取るところから取り合いを見積もり、成りなら最初に成り得を加える。
先頭、置換表の手、王手を掛ける手、王手回避は残す。
これは移動先での局所的な損得の近似であり、駒を捨てて攻める手を読み落とす可能性がある。

**history pruning**は、深さ3以下の非PVノードで、`履歴スコア < −2148 × 深さ`となる静かな手を省く。
履歴スコアはmain historyと重み付きcontinuation historyの和である。
先頭の手、王手を掛ける手、王手回避は残す。

## LMP

LMPは、並べ替えの後ろにある静かな非王手を、対象手の個数で制限する。
深さによる適用上限はなく、非PVかつ王手されていないノードに適用する。
盤上の手の上限は次の式で決まる。

```text
上限 = (4 + 深さ²) / (2 − improving)
```

整数除算なので、改善なしの深さ1、2、3では、それぞれ2、4、6手までとなる。
改善ありなら5、8、13手まで許す。
比較用の評価値が欠けた場合も、改善なしの上限を使う。

駒打ちは盤上の手とは別に数える。
駒打ちの上限は、盤上の上限を2で割り、最低1手を残した値である。
個数は、先行するfutilityやhistory pruningで省かれず、LMPの判定まで到達した対象手を数える。

## LMR

LMRは、順序の遅い静かな手を通常より浅い幅1の探索窓で読む。
非PVノードでは3手目以降、PVノードでは4手目以降を候補とし、王手回避には適用しない。
王手を掛ける静かな手も、静かな非王手と同じ縮小量で読む。

縮小量は1段を1024とする細かい単位で積み、最後に段へ切り捨てる。
基礎値は`ln(深さ) × ln(手の添字) × 100 / 190`段である。
添字は0始まりで、事前計算する表では深さを63、添字を1023以下に収める。
持ち駒の多い局面でも、64手目以降の縮小量は対数式に従って増える。
基礎値に次の補正を加える。

| 条件 | 補正 |
|---|---|
| 今PV上にあるか、置換表のPVビットが立っている（ttPv） | 約1段浅く |
| 改善なし | 約0.9段深く |
| cut node（fail highが見込まれるnode） | 約1.7段深く |
| 置換表の手が捕獲 | 約0.5段深く |
| このnodeの子で既にβカットが2回以上起きた | 約0.8段深く |
| 履歴スコア | 最大±2段 |
| 静的評価へ加えた補正の絶対値 | 128点で1段浅く、最大1段 |
| 探索窓の幅 | 幅1では補正なし、通常のaspiration窓まで最大半段浅く |

最終的には`0..=深さ−2`に収めるため、実際に浅くなるのは深さ3以上で、子の深さは1以上に保つ。

**cut node**は、親が幅1の窓で「fail highするはず」と見込んで読ませたnodeである。
PVの子はcut nodeでなく、cut nodeの最初の子はcut nodeでない（all node）、縮めて読む子はcut nodeとして扱う。
**PVビット**は、PV上で読まれたnodeを置換表に記録した印で、PVを外れた後もそのnodeの縮小を控える。

浅い探索がalphaを超えたら、幅1の探索をやり直す。
それまでの最善値を大きく超えていれば通常より1段深く、わずかに超えただけなら1段浅く読み直し、その静かな手を直前の手に続く手としてcontinuation historyで褒める。
その結果がalphaとbetaの間なら、PVSの通常の窓でも読み直す。
浅い探索がalphaを超えなかった手は、そのまま確定するため、読み落としの可能性が残る。

縮めて読まれた子のnodeは、自分の静的評価を見て深さを事後に調整する。
親が3段以上縮めたのに相手の評価が悪化していなければ1段深く、2段以上縮めて双方の評価の和が高ければ1段浅く読む。

## singular extension

枝刈りと逆向きに、特定の手だけを深く読む仕組みもある。
置換表に最善手と下限値（`Lower`か`Exact`）があり、そのdepthが現在より3浅い以内なら、その手を除いた残りの手を半分のdepthで読む。
窓は置換表の値から`2 × depth`を引いた値`singular_beta`の直下に置く。
除いた手がどれも`singular_beta`に届かなければ、置換表の最善手だけが局面を支えていると見て、その手を1手深く読む。
逆に除いた手でも`singular_beta`に届き、しかも`singular_beta`がbeta以上なら、betaを超える手が複数あるので、このノードを`singular_beta`で打ち切る（multi-cut）。

判定の探索は通常のノード探索と同じ並べ替えと枝刈りを使い、除いた手だけを読まない。
その結果は最善手を含む本来の値ではないので、置換表では打ち切らず、保存もしない。
深さ5未満のノード、root、詰みの値、iterationのdepthの2倍以上のplyでは試さない。

## 枝刈り後の置換表

主探索は、beta cutoffを起こした結果を`Lower`、窓内でalphaを上げた結果を`Exact`、alphaを上げられなかった結果を`Upper`として保存する。
ここでの`Exact`は、実際に行った探索で窓内の値を得たことを表す。
枝刈りや縮小で読み落とす可能性があるため、元の深さの全幅minimax値との一致を保証するものではない。

静止探索は別の保存条件を使う。
枝刈りしたノードでは、beta cutoffで得た`Lower`だけを保存する。
詳細は[置換表](tt.md)と[静止探索](qsearch.md)を参照。
