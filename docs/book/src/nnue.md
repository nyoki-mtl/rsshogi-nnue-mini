# 評価関数

このエンジンは`aonly1024_i8_progress8_v1`仕様の`.rsnn`評価関数を使う。
旧I16 A-onlyと旧mobile-v1のpackageは現在のconsumerでは読み込めない。
学習済みモデルは、[v0.3.0 Release](https://github.com/nyoki-mtl/rsshogi-nnue-mini/releases/tag/v0.3.0)でバイナリに内蔵して配布する。
モデル単体の`.rsnn`は配布しない。

## 評価の仕組み

両玉を含む14種類の盤上駒と持ち駒のunary slotを、双方の視点で2,344次元のA特徴へ符号化する。
共有FT重みは対称I8（-127〜127、スケール1/256）、biasと累積値はI16で保持する。
各視点1,024幅で、半分ずつの積をpoolingし、手番側から順に連結する。
固定KP進行度が8本の後段から1本を選ぶ。後段は32幅2層で、符号付き値の二乗成分とclipped ReLU成分、浅い層から出力への経路を使う。
A特徴から8個のPSQT和も計算する。

探索中は着手の差分でFTとPSQTを更新し、undoで親frameへ戻る。
玉移動も通常のA特徴差分として扱う。KP進行度は独立したスカラー和で、自玉移動時にはその視点を再計算する。
null moveでは累積値を変更せず、出力の視点順序を切り替える。

推論は整数演算で行い、AVX2、NEON、scalarの経路を備える。
NNとPSQTを合成した整数出力を固定値16で割り、探索に渡す評価値を±31,753に収める。
出力スケールはUSIやSPSAでは変更せず、探索側のパラメータを調整する。対象端末の速度、実モデルの適格性と棋力は別途検証する。

## サイズとpackageの互換性

量子化tensorは2,758,944バイト、固定KP進行度は497,048バイトで、合計3,255,992バイトとなる。
containerのmetadataとpaddingはこの合計に含めない。
FTを実行時にI16の重み表へ展開せず、scalar、AVX2、NEONの更新時に符号拡張する。
探索用の累積値stackと置換表などのメモリは別途必要になる。

新recipeは旧I16版と互換ではなく、既存packageのrecipe名だけを変更して読み込むことはできない。
trainerはFT重みを-127〜127へ収める量子化と、この仕様のdescriptorによるexportに対応する。
配布モデルの適格性と対象端末での実行確認は、各リリースの確認範囲として区別する。

## 読み込み時の確認

`.rsnn`のdigest、評価仕様、tensorの型と形状、FT・PSQT・全結合層の数値範囲を検査する。
固定`kp-progress.bin`のheaderとSHA-256も照合する。
